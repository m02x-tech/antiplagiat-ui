# Интерфейс раздела «Антиплагиат»

Витрина одного раздела внутреннего приложения по управлению портфелем
научных программ. Здесь **только интерфейс**: шаблоны, стили и маленькое
демо-приложение, которое их рисует на вымышленных данных.

```bash
pip install -r requirements.txt
uvicorn app:app --reload
# http://127.0.0.1:8000/antiplagiat
```

## Чего здесь нет и не будет

Ни базы, ни документов, ни реальных данных. Основной репозиторий закрыт, и
эта витрина отделена от него намеренно: боевой корпус — отчётность по
научным программам, в именах файлов которой стоят фамилии людей. **Все имена,
названия и числа в `fixtures.py` выдуманы.** Если правка требует настоящих
данных, значит её надо делать не здесь.

## Что показывает раздел

Для каждого отчёта — долю текста, совпадающую с другими документами корпуса.
Совпадение ищется дословное: прогоны от 16 слов подряд.

Три вещи, без понимания которых интерфейс получится неправильным.

**1. На листе дерева три числа, а не одно.** Взвешенное по объёму среднее,
худший документ и число документов. Простое арифметическое среднее врёт:
в одном листе бывает от 1 до 72 документов, а объёмы различаются до 30 000
раз, так что один короткий плохой документ либо тонет, либо топит весь лист.

**2. Кратность донора важнее процента.** У каждого совпадения есть число —
сколько независимых документов содержат тот же фрагмент. Замер по всему
корпусу показал: почти всё, что механически считается «заимствованием»,
разделяют три и более несвязанных документа. Это типовой текст — разделы
ГОСТ, методики, стандартные формулировки, — а не перенос.

Отсюда жёсткое требование к формулировкам: **фрагмент, который есть в сорока
отчётах, нельзя подписывать словом «заимствовано».** Интерфейс, называющий
шаблон плагиатом, хуже отсутствующего: им один раз воспользуются и перестанут
верить. Переключатель «без типовых» отсекает места с кратностью от 3.

**3. Три состояния, которые нельзя путать:**

| Состояние | Что значит | Как выглядит |
|---|---|---|
| «нет индекса» | по программе поиск не строился, искать не в чем | плашка вместо дерева |
| «не посчитано» | расчёт возможен, но не запускался | серый бейдж, **не** 100 % |
| 100 % | посчитано, совпадений нет | зелёный бейдж |

## Что можно менять

Всё, что касается вида: `templates/*.html`, `static/style.css`, вёрстка,
типографика, состояния, подписи, поведение переключателей.

## Чего менять нельзя

- **Имена полей в `models.py`.** Боевое приложение читает из базы именно их;
  переименование означает, что правку нельзя перенести обратно. Нужно новое
  поле — скажите об этом в описании правок, оно появится на стороне базы.
- **Адреса маршрутов и имена параметров** (`variant`, `cutoff`, `k`, `path`).
  По ним строятся ссылки в боевом приложении.
- **Красный цвет строки дерева.** Он уже занят под нулевое покрытие
  документами. Оригинальность показывается бейджами и пилюлями; два разных
  смысла у одного цвета на одном дереве недопустимы.

## Два переключателя, и они независимы

1. `variant`: `default` — совпадения внутри своего проекта заглушены (это
   авторский задел, а не заимствование); `no_same_project` — не заглушены.
2. `cutoff`: `all` — все совпадения; `unique` — без типовых, то есть без мест
   с тремя и более независимыми донорами.

Работают вместе, все четыре сочетания должны быть достижимы и осмысленно
подписаны.

## Как правки возвращаются

Отдельная ветка и pull request с описанием того, что изменено и почему.
Изменённые файлы переносятся в основной репозиторий копированием — поэтому
важно, чтобы правки лежали в `templates/` и `static/`, а не расползались по
демо-обвязке (`app.py`, `fixtures.py`), которой в боевом приложении нет.
